GSE01 렌더링 프로토타입 / 2026-09-08
가제: The Ember Remains (이름 확정 아님)

1. 이번 구현의 목적
현재 기획서의 중세·암울함·작은 희망을 실제 게임 화면으로 살펴보기 위한
C++ / OpenGL 프로토타입이다. 완성된 게임이나 미술 최종안은 아니다.
외부 이미지 없이 도형, 색, 깊이 정렬, 그림자, 안개와 불빛으로 표현한다.
빌드 및 실행 결과 확인은 사용자에게 맡긴다.

2. 사용자 빌드와 실행
- 기존 SimpleGame.sln을 Visual Studio에서 연다.
- 기존 v143 도구 집합과 Windows SDK를 사용하는 Debug / x64 구성을 권장한다.
- 프로젝트를 빌드한 후 실행한다. 이번 작업에서는 빌드·실행하지 않았다.
- OpenGL 3.3을 지원하는 그래픽 환경이 필요하다.
- 빌드 후 셰이더는 실행 파일 옆 Shaders 폴더로 복사된다.
- 플랫폼에 맞는 기존 freeglut.dll / glew32.dll도 출력 폴더로 복사한다.
- 소스 폴더와 실행 파일 폴더 어디에서 시작해도 셰이더는 실행 파일 기준으로 찾는다.
- 오류 시 콘솔의 셰이더·초기화·저장 메시지를 확인한다.

3. 처음 나타나도록 구성한 장면
- 1280 x 800 논리 화면의 아이소메트릭 마을과 숲.
- 중앙 모닥불, 따뜻한 창문이 있는 집, 폐허, 나무, 작은 기념비.
- 청록색 망토와 등불을 가진 플레이어, 불가의 갈색 망토 NPC.
- 상단 지역·삶·전승 NPC 수, 좌측 작은 친절 안내, 우측 주변 위치 표시.
- 창 비율이 달라지면 화면 비율을 보존하고 여백을 둔다.
- 플레이어를 가리는 일부 나무·집은 반투명해진다.

4. 조작
WASD 또는 방향키: 화면 방향으로 이동
Shift: 달리기
E: 가까운 NPC와 대화 / 기념비 조사
K: 죽음과 전승 시연 확인창
Enter: 확인창에서 전승 확정
Esc: 확인창 취소 / 일반 화면에서는 저장 후 종료
F3: 청크 경계와 현재 좌표 표시
F5: 수동 저장
F6: HDR 후처리 전체 켜기/끄기 (직접 렌더링과 비교)
F7: 블룸 켜기/끄기
F8: 비넷 켜기/끄기
F9: 화면 가장자리 블러 켜기/끄기
PageUp / PageDown: 노출 증가/감소
Home: 후처리 기본값으로 복원
창 닫기: 저장 시도 후 종료

5. 사용자가 확인할 순서
① 실행 시 지형·인물·UI가 표시되는지 확인한다.
② 이동·달리기·카메라 추종, 집·나무·돌과의 충돌을 확인한다.
③ 모닥불 옆 NPC에 접근해 E를 누른다. 나무 새 선물과 재대화 반응을 확인한다.
④ 마을의 기념비에 접근해 E를 누른다. 작은 꽃과 발견 수 변화를 확인한다.
⑤ F3으로 경계를 켜고 마을 밖을 탐험한다. 숲이 이어지고 로딩 청크는 49개로 유지된다.
⑥ K → Enter로 전승을 시연한다. 전승 NPC 수가 한 명 증가하고 마을에서 다시 시작한다.
⑦ 사망 위치에 돌아가 전승 NPC의 색과 대사를 확인한다.
⑧ F5 또는 Esc로 저장하고 다시 실행해 위치·NPC·발견·선물을 확인한다.
⑨ 창을 가로·세로로 바꾸고 다른 앱으로 전환해 입력과 표시를 확인한다.
⑩ 모닥불과 창문 곁에서 F6/F7로 발광과 빛 번짐 차이를 비교한다.
⑪ F8/F9를 전환하면서 중앙은 선명하고 가장자리는 어둡고 흐려지는지 확인한다.
⑫ F3 정보 패널에서 효과 상태와 노출을 확인하고 PageUp/PageDown으로 조절한다.
⑬ 대화와 전승 확인창을 열어 후처리와 관계없이 글자가 선명한지 확인한다.

6. 전승 시연의 임시 규칙
- 전투가 없어 K 키로 사망 과정을 시연한다. Enter 확인 전에는 상태가 바뀌지 않는다.
- 죽은 위치에 고유 ID를 가진 NPC 한 명을 남긴다.
- 모닥불 NPC와 상호작용한 삶: 호의 성향, 황갈색 망토와 돌봄 대사.
- 호의 기록 없이 20타일 이상 이동한 삶: 탐험 성향, 청록색 망토와 길에 관한 대사.
- 그 외: 조용한 성향, 보라색 망토와 익숙한 장소에 관한 대사.
- 다음 삶은 모닥불 근처에서 시작한다. 이는 미정 사항을 시연하기 위한 임시 선택이다.
- 선물은 이 프로토타입에서 세계 공통의 기념품으로 유지한다.
- 감정 모델, 복합 성향, 자율 NPC 행동은 아직 없다.
- 모든 대사는 규칙 기반 문장이다. 외부 AI 호출이나 AI 생성 대사가 아니다.

7. 월드 생성과 영속성
- 8 x 8 타일 청크를 플레이어 주변 7 x 7개만 유지한다.
- 양수·음수 좌표로 이동할 수 있고 별도의 맵 끝은 두지 않았다.
- 고정 시드 20260908과 좌표 해시로 숲·돌·기념비를 결정한다.
- 고정 시드는 재실행 시 같은 장소를 만드는 초기 단계 장치이다.
- 기존 지형은 생성기 v1을 유지한다는 조건에서 재현된다.
- 조사된 기념비, 플레이어, 전승 NPC, 선물 상태는 별도로 저장한다.
- 생성기 수정 시 기존 지형 보존을 위한 청크 스냅샷·마이그레이션이 추가로 필요하다.
- NPC끼리 사건이나 마을을 만들어 내는 창발적 콘텐츠 생성은 아직 구현하지 않았다.

8. 저장 파일과 실패 처리
- 실행 파일 폴더 / Saves / prototype_v1.txt
- 10초 간격 자동 저장, 상호작용·전승·수동 저장·종료 시 저장.
- 임시 파일 기록 성공 후 원본을 교체한다.
- 전승 저장에 실패하면 해당 전승의 메모리 상태도 되돌린다.
- 손상 또는 지원하지 않는 저장 파일은 자동으로 덮어쓰지 않는다.
- 화면에 '저장 불가'가 보이면 저장 폴더 권한과 콘솔을 확인한다.
- 잘못된 저장 파일을 확인한 후 새로 시작하려면 앱을 닫고 파일을 별도 장소에
  백업한 뒤 기존 파일의 이름을 바꾼다. 기존 진행은 새 세션에 자동 합쳐지지 않는다.
- Esc는 저장 성공 시 종료한다. 저장 불가 상태에서 창 닫기를 사용하면 현재
  세션의 저장되지 않은 진행은 잃을 수 있다.
- 여러 게임 창을 같은 저장 파일로 동시에 실행하는 것은 지원하지 않는다.
- Debug와 Release 등 출력 폴더가 다르면 각각 별도 진행을 가진다.
- Saves 폴더는 Git 추적에서 제외한다.

9. 변경 파일의 역할
SimpleGame.cpp: 초기화, 입력, 타이머, 창 크기, 종료 수명 관리.
Renderer.h / Renderer.cpp: 도형·글자 배치 렌더링과 셰이더 관리.
Game.h / Game.cpp: 절차 지형, 이동·충돌, 장면, UI, 상호작용, 전승과 저장.
Shaders/SolidRect.vs / SolidRect.fs: 위치·색상 기반 배치 렌더링 셰이더.
SimpleGame.vcxproj / .filters: 새 소스 등록, C++17, 리소스 복사.
stdafx.h: Windows 매크로와 표준 라이브러리 충돌 방지.
.gitignore: 로컬 저장 데이터 제외.

10. 현재 한계와 다음 단계
- 완성된 RPG가 아니라 첫 렌더링·탐험·전승 시연 단계이다.
- 도형 기반 임시 미술이며 이미지 스프라이트와 사운드는 없다.
- NPC 대사, 이벤트와 화면 안내는 한국어다. Windows의 맑은 고딕 글꼴을 사용한다.
  UTF-8 문장을 Unicode로 변환하고 글자 모양을 캐시하여 기존 도형 배치로 그린다.
  별도 폰트 파일을 배포하지 않으며 모든 빌드 구성에 /utf-8 옵션을 지정했다.
- 전투·체력·장비·인벤토리·퀘스트·경제는 아직 없다.
- 전승 NPC는 제자리에 머무른다. 성향 기반 이동·일과·관계는 후속 단계이다.
- 지형 생성과 저장은 동기식이다. 장시간 플레이 시 백그라운드 처리로 확장해야 한다.
- 월드 좌표는 double과 64비트 청크 키를 사용하고 화면은 카메라 상대 좌표로 계산한다.
  생산 단계에서는 청크+지역 좌표의 정밀도, 극단적 좌표 범위와 이동을 더 검증해야 한다.
- 전승 NPC는 한 배열에서 조회한다. 인구가 늘면 지역 인덱스와 저장 분리가 필요하다.
- 현재 파일 로딩 상한은 전승 NPC 10만 명, 발견 기록 100만 개다.
  이는 손상된 파일 방어용 시제품 상한이며 무한 운영을 보장하는 저장 구조가 아니다.
- 프로토타입은 원격 저장소에 자동 커밋하거나 푸시하지 않는다.

후속 우선순위:
렌더링·조작·한글 가독성 피드백 → 실제 스프라이트 → 전투·사망 흐름 확정 →
성향 기반 NPC 행동 → 청크 영속 저장 강화 → 기억 기반 AI 대화 연결.

11. HDR 및 화면 후처리 (2026-09-08 추가)

렌더링 순서:
① 월드 도형의 일반 색상을 sRGB에서 선형 색상으로 변환한다.
② 1280 x 800 RGBA16F 프레임버퍼에 월드를 그린다.
   모닥불·불티·창문·등불·미발견 기념비는 1보다 큰 발광값을 가진다.
③ 밝은 부분을 추출하고 절반 해상도에서 가로·세로 Gaussian 블러를 반복한다.
④ 별도로 장면 전체의 흐린 사본을 만든다.
⑤ 중앙에서 멀어질수록 원본과 흐린 사본을 부드럽게 혼합한다.
⑥ 블룸을 합성하고 가장자리를 점진적으로 어둡게 하는 비넷을 적용한다.
⑦ 노출과 지수형 톤 매핑 후 sRGB로 한 번 변환하여 창에 출력한다.
⑧ NPC 상호작용 표시, 한글 대사, HUD, 확인창을 선명하게 덧그린다.

기본값 (Renderer.h의 PostProcessSettings):
- 노출 1.05 (조작 범위 0.25~3.0)
- 블룸 강도 0.45, 밝기 임계값 1.0
- 비넷 강도 0.38
- 가장자리 블러 강도 0.85
- 모든 효과 기본 켜짐. 설정은 현재 실행에만 적용하고 저장 파일은 변경하지 않는다.

구현 세부:
- F6을 끄면 톤 매핑을 포함한 모든 후처리를 우회하여 장면을 직접 그린다.
  비교 대상도 동일한 현재 발광 색상을 사용하며, 과거 버전 화면을 재현하는 기능은 아니다.
- F7/F9를 끄면 해당 블러 패스도 건너뛴다. F8만 끄면 비넷 강도만 0으로 설정한다.
- 종전 사각형 띠로 만든 가장자리 음영은 제거했다. 안개는 장면 요소로 유지한다.
- 모닥불·등불·기념비 주변의 수동 타원형 광륜은 제거했다.
  광원 형상만 HDR 장면에 그리고 빛 번짐은 후처리 블룸으로만 만든다.
- 블룸은 반해상도에서 가로·세로 블러를 4회 반복한다. 가장자리 블러는 기존 설정을 유지한다.
- F6이 켜진 상태에서 F7을 끄면 발광부 자체는 밝게 남고 주변 블룸만 사라져야 한다.
  모닥불의 돌 테두리, 물체의 바닥 그림자, 안개는 광륜이 아니므로 유지한다.
- 블룸은 화면상 빛 번짐이다. 지형의 실제 조명이나 그림자를 계산하는 광원 시스템은 아니다.
- 창 크기 변경 시 1280 x 800 논리 해상도를 유지해 블러 반경과 버퍼 메모리가 일정하다.
  큰 화면에서는 장면이 확대되며, 디스플레이 원래 해상도로 재생성하는 옵션은 아직 없다.
- HDR 버퍼 1개와 반해상도 버퍼 4개를 사용한다. 색상 버퍼는 합계 약 16 MB다.
- 프로그램·텍스처·프레임버퍼·VAO는 종료 시 해제한다.
- 후처리 셰이더/버퍼 초기화 실패 시 콘솔에 이유를 남기고 직접 렌더링으로 대체한다.
- 추가 셰이더: Fullscreen.vs, Filter.fs, PostProcess.fs.
  프로젝트 빌드 후 모든 .vs/.fs 파일을 실행 파일 옆 Shaders로 복사한다.
- 수정 파일은 Windows CRLF 줄바꿈과 UTF-8로 저장한다.

적용 범위:
내부 HDR 렌더링과 SDR 톤 매핑이다. HDR10 출력이나 Windows HDR 디스플레이 전환은 아니다.
가장자리 블러는 화면 위치 기준 효과이며 실제 거리 기반 피사계 심도는 아니다.
빌드·실행·화면 결과 검증은 사용자에게 맡겼으며, 이번 변경에서는 수행하지 않았다.
