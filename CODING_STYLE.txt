GSE01 코드 작성 규칙
2026-09-14

목표: 줄바꿈을 넉넉히 사용해 실행 흐름과 코드 구조가 쉽게 보이도록 한다.
적용 대상: 직접 작성한 C++ 소스·헤더와 GLSL 셰이더.
외부 라이브러리(Dependencies), 빌드 출력물, 저장 데이터는 대상에서 제외한다.

1. 중괄호는 다음 줄에 둔다 (Allman).
2. 조건문과 반복문은 본문이 한 문장이더라도 중괄호를 사용한다.
3. 한 줄에 여러 실행 문장을 넣지 않는다.
4. 짧은 함수, 구조체, 열거형도 여러 줄로 작성한다.
5. 들여쓰기는 공백 4칸을 사용한다.
6. 함수·타입 정의 사이에는 빈 줄을 한 줄 둔다.
7. 한 줄은 100열을 기준으로 한다. 한글 대사와 문자열은 자동 분할하지 않는다.
8. 긴 함수 호출과 선언은 인자·매개변수를 한 줄씩 배치한다.
9. 포인터·참조 표기는 타입 쪽에 붙인다 (Renderer*, Renderer&).
10. UTF-8과 Windows CRLF 줄바꿈을 유지한다.
11. include 순서는 자동으로 바꾸지 않는다. stdafx.h를 첫 include로 유지한다.
12. 동작·이름·값의 변경과 서식 변경을 구분한다.

예시:

void UpdatePlayer(float deltaTime)
{
    if (deltaTime <= 0.f)
    {
        return;
    }

    MovePlayer(deltaTime);
    UpdateCamera();
}

자동 서식 설정은 프로젝트 루트의 .clang-format을 기준으로 한다.
현재 설정은 설치된 clang-format 22.1.3으로 적용했다.
특정 파일을 정리하려면 프로젝트 루트에서 아래 형식으로 실행한다.

clang-format -i SimpleGame/Game.cpp SimpleGame/Game.h

셰이더는 확장자가 .vs/.fs이므로 C++ 문법 기반 서식으로 명시한다.

clang-format --assume-filename=shader.cpp -i SimpleGame/Shaders/PostProcess.fs

다른 버전에서 설정 옵션을 인식하지 못하면 설정을 삭제하지 말고
프로젝트와 같은 formatter 버전을 사용한다.
이번 작업에서는 빌드·실행을 하지 않았다.
